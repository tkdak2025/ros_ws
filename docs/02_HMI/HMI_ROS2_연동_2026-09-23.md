# 검사 PC ↔ HMI PC ROS 2 연동

갱신: 2026-09-25. 이 문서는 두 PC 기동과 연결 확인을 위한 요약입니다. 필드·QoS·서비스 응답·레시피 규칙은 [HMI 검사 측 인터페이스 가이드](../작업내역/03_HMI_검사측_인터페이스_가이드_2026-09-23.md), 로봇상태와 작업상태의 구분은 [상태 분리 규격](HMI_상태분리_인터페이스_2026-09-23.md)을 기준으로 합니다. 이전 단일 `/cable_inspection/status`와 토픽 `START` 계약은 사용하지 않습니다.

## 실행 구성

검사 PC에서 로봇/RG2 드라이버를 별도로 실행한 뒤 Main·Judgment·Robot State를 시작합니다. HMI 프로그램은 HMI PC에서 별도로 시작하며 검사 측 launch는 HMI를 실행하지 않습니다.

```bash
cd /home/rokey/Desktop/ROKEY9/ROKEY_3/PRJT_CCCIS/ros_ws
source /opt/ros/jazzy/setup.bash
source ~/ws_cobot_pjt/ws_dsr/install/local_setup.bash
source install/local_setup.bash
ros2 launch cable_inspection inspection.launch.py control_mode:=hmi robot_mode:=real
```

가상 드라이버로 모션을 확인할 때만 `robot_mode:=virtual`을 사용합니다. 해당 모드도 가상 로봇/RG2 서비스가 필요합니다. 검사 패키지와 HMI mock·기존 robot_monitor_node가 같은 운영 상태를 중복 발행하지 않도록 구성합니다.

## 두 PC 통신 조건

양쪽 ROS 2 배포판, `cable_interfaces` 버전, ROS_DOMAIN_ID와 DDS discovery 설정을 맞춥니다. 현재 검사 측 조회 환경의 예시는 `ROS_DOMAIN_ID=50`, `RMW_IMPLEMENTATION=rmw_fastrtps_cpp`, `ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`입니다. 실제 운전 환경값을 확인해 양쪽 PC에 동일하게 적용합니다. HMI PC도 `cable_interfaces`를 빌드해야 서비스와 결과 메시지를 사용할 수 있습니다.

| 방향 | 주소 | 타입 | 용도 |
|---|---|---|---|
| HMI → 검사 | `/cable_inspection/start` | `cable_interfaces/srv/StartInspection` | request_id와 전체 `InspectionRecipe` 접수 |
| HMI → 검사 | `/cable_inspection/command` | `std_msgs/msg/String` JSON | PAUSE, RESUME, STOP, HOME_RETURN, SYNC |
| HMI → 검사 | `/cable_inspection/hmi_heartbeat` | `std_msgs/msg/Empty` | HMI 제어 연결 감시 |
| 검사 → HMI | `/cable_inspection/work_status` | `std_msgs/msg/String` JSON | 작업 상태·진행·명령 응답 상태 |
| 검사 → HMI | `/cable_inspection/robot_status` | `std_msgs/msg/String` JSON | 로봇·그리퍼 계측 상태 |
| 검사 → HMI | `/cable_inspection/execution_snapshot` | `std_msgs/msg/String` JSON | 접수한 실행 레시피 복사본 |
| 검사 → HMI | `/cable_inspection/judgment_result` | `cable_interfaces/msg/InspectionResult` | Point별 PASS/FAIL/SYSTEM_ERROR |
| 검사 → HMI | `/cable_inspection/log` | `std_msgs/msg/String` JSON | 실행 로그 |

HMI의 원본 레시피 DB와 결과 이력 DB는 HMI 담당 범위입니다. 검사 측은 레시피 복사본을 실행하며, 결과 토픽에 저장 ACK나 과거 결과 재전송 기능은 없습니다. `ListRecipes/GetRecipe/SaveRecipe/QueryResults`는 공통 패키지의 타입 정의일 뿐 검사 측 서버가 아닙니다.

## 연결 확인

```bash
ros2 service type /cable_inspection/start
ros2 topic info /cable_inspection/work_status --verbose
ros2 topic info /cable_inspection/robot_status --verbose
ros2 topic info /cable_inspection/judgment_result --verbose
ros2 topic hz /cable_inspection/hmi_heartbeat
```

대기 중 `work_status`는 변경 또는 SYNC 응답 시 발행하므로 수신 공백만으로 단절을 판단하지 않습니다. HMI는 heartbeat를 주기적으로 전송하고 SYNC 응답으로 Main 생존을 확인합니다. `work_status`와 `execution_snapshot` 구독자에는 TRANSIENT_LOCAL QoS를 맞춥니다. 서비스 `accepted=true`는 접수 성공이며 장비 초기화·검사 완료를 뜻하지 않습니다. 실제 START와 HOME 명령은 로봇을 움직일 수 있으므로 장비 운전 절차에서 확인합니다.
