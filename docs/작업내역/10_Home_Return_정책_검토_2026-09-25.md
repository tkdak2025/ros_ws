# 10. Home Return 정책 검토

기준: 현재 `cable_inspection` 소스와 `system_recipe.json`, 2026-09-22 #02 설계, PR #9·#10 및 이후 사용자 결정. 이 문서는 실물 경로의 안전성을 증명하지 않는다.

## 결정 경과

| 시점 | 내용 |
|---|---|
| 최초 #02 설계 | 작업영역 내부는 Grip Relaxation → Tool 접근축 반대 Safe Escape → Work Access → Home. 외부는 Home 경로. |
| PR #9 구현 | 내부도 Work Access → 전체 0도 Home. Relax/Escape는 호출하지 않음. |
| 사용자 확인 | Tool +Z 진입으로 케이블 파지를 안정화하고, 현재 Tool 접근축 반대 후퇴로 LAN 공유기처럼 인접한 선과의 충돌·간섭을 줄인다. 먼저 그리퍼 약 25 mm Open, 기존 0도 Home 직접 복귀. |
| 경계 논의 | work_area 경계 밖까지 나가려면 30 mm로 부족함을 확인. contact_area를 추가하지 않고 Tool 반대 방향 30 mm 후퇴 후 Access 이동하기로 정함. 30 mm 적합성은 실물 확인 대상. |
| 현재 코드 | 내부: Open 25 mm와 실측 폭 확인 → 현재 Tool −Z 30 mm MoveL과 목표 도달 확인 → Work Access MoveJ → 0도 Home MoveJ. 외부: 0도 Home MoveJ. `safe_home_route=[home_pose]`. |

## 발생할 수 있는 문제

| 범주 | 확인 내용 | 현재 상태 |
|---|---|---|
| 방향·좌표 | Safe Escape는 검사 레시피의 Entry 자세가 아닌 **현재 TCP 자세**와 시스템 `tool_approach_axis=[0,0,1]`로 Tool −Z를 계산한다. 현재 자세가 Entry 자세와 다르면 Pull의 −Z와 실제 BASE 방향이 다르다. | 설정·계산 확인, 현장 자세별 검증 필요 |
| 분기·중복 | Work Access `[532.25,34.8,497.08]`이 `work_area` 내부다. 종전 구현은 Work Finish에서 Open→후퇴→Access 재이동을 반복했다. | 사용자 결정으로 검증된 Access에서 직접 Home으로 수정 |
| 경로·간섭 | 일반 Home을 Access 위치에서 시작하면 Tool −Z 30 mm 목표는 약 `[505.62,33.76,510.86]`이고 이후 Access로 돌아온다. Work Finish의 검증된 Access에서는 이 왕복을 생략한다. Work Access→Home MoveJ의 중간 경로 충돌 검사는 없다. | 실물 저속 확인 필요 |
| 그리퍼 | Open 25 mm의 실측 폭이 ±2.5 mm 이내인지 확인한 뒤 후퇴한다. RG2 힘 증감 명령은 기존 폭 목표를 재전송하므로 Open 폭을 먼저 명령한다. `gripper_busy`는 기록만 하고 Home 동작 제한에 사용하지 않는다. | 명령 순서와 폭 확인 적용, 실물 케이블 해제 확인 필요 |
| 종료·복구 | 후퇴 목표 미도달, Open 실패, 서비스/모션 오류는 Access/Home으로 건너뛰지 않는다. STOP/보호정지 후 자동 복귀하지 않는다. | 기존 정책 유지 |
| 기록 | 오프라인 테스트는 명령 순서·실패 차단을 확인했으나 실제 케이블 해제, 30 mm 거리, 링크/그리퍼 간섭을 검증하지 못한다. | 실물 확인 필요 |

## 검토할 결론

1. 케이블 접촉이 가능한 미확인 작업영역 자세에서는 Open→현재 Tool −Z 30 mm→Access→Home을 유지한다.
2. 이미 **도달이 확인된 Work Access**에서는 케이블 방향 후퇴가 의미 없고 오히려 왕복 동작을 만든다. 이 경우 실제 TCP가 Access 자세에 있는지 재확인한 뒤 직접 0도 Home으로 이동하도록 확정·반영했다. 수동 HOME과 START에서 단지 좌표가 가깝다는 이유만으로 이 예외를 적용하지 않는다.
3. Work Access→Home 경로, Entry pose별 30 mm 후퇴 경로, Open 25 mm의 실제 해제 여부를 현장에서 확인해야 한다.


## 적용 결과

Work Finish에서 Access 도달 후 `home_return(at_verified_access=True)`를 호출한다. 현재 TCP가 설정된 Access task의 위치 0.5 mm/자세 1도 허용오차 이내인지 재확인한다. 만족하면 Open/후퇴/Access 재이동 없이 0도 Home 경로를 실행하며, 실패하면 `WORK_ACCESS_NOT_REACHED`로 Home을 차단한다. 일반 START·수동 HOME의 동작은 유지한다.

오프라인 검사 패키지 테스트: 164 passed, 1 skipped (Busy 비의존 변경 후). 실물 로봇 이동, 경로 간섭 및 그리퍼 해제 검증은 수행하지 않았다.

## RG2 상태값 추가 확인 (2026-09-25)

현재 외부 OnRobot 드라이버는 Modbus 상태 레지스터 `gsta` 전체를 `status["busy"]`로 사용하고, 0이 아니면 JointState effort에 명령 힘을 채운다. 검사 코드는 effort의 0 여부를 `gripper_busy`로 기록한다. 따라서 이 값의 true는 실제 동작 중(원시 bit 0)을 단독으로 의미하지 않는다. 정상·반체결 과거 실물 샘플 모두 Open 25 mm 명령 후 폭 허용범위에 도달하고 기록상 false가 된 구간은 있으나, 이는 현재 Home Return의 Safe Escape 물리 경로를 검증한 것이 아니다. 2026-09-25 사용자 결정에 따라 이 값은 Home 동작 조건에서 제거하고 로그에만 남긴다. Home 완료의 남은 실물 확인 항목은 Open 25 mm의 케이블 해제 여부, Tool −Z 30 mm 및 Work Access→0도 Home 경로 간섭이다.
