# 18. 검사파트 작업 최종결론 — 2026-09-25

이 문서는 이번 구조 정리와 운영 정책 논의의 최종 정리다. 앞선 작업내역은 당시 판단의 기록이며, 현재 적용 기준은 [v4 문서 묶음](../v4/00_문서안내_v4.md)이다. 여기서 최종결론은 실물 검증까지 완료했다는 뜻이 아니다.

## 1. 문서 관리 결론

번호가 붙었던 작업 문서를 이 폴더로 모았다. 기존 번호와 파일명을 유지하고, 이동에 따른 Markdown 링크만 보정했다. `11_` 문서 두 개도 이력 식별을 위해 재번호하지 않았다. 구버전 설계 묶음 내부의 `00_` 색인은 그 버전의 구성요소이므로 분리하지 않았다.

BRD는 v1의 v0.2, 컨셉은 v2, 상세 시퀀스는 v3 및 이후 작업내역을 토대로 v4로 갱신했다. 이전 버전의 MD/PDF/DOCX는 보존한다. 새로운 운영 기준은 v4 Markdown이며, 구버전 PDF는 v4가 아니다.

## 2. 책임과 코드 구조

| 영역 | 최종 책임 | 다른 영역과의 경계 |
|---|---|---|
| Robot | M0609 통신·raw 명령·Robot API·비동기 로봇 상태 수집 | 검사 순서/케이블 판정은 맡지 않음 |
| GripperTool | RG2 통신·raw 명령·Gripper API·그리퍼 피드백 | Robot과 독립하여 장비 교체 가능 |
| Recipe | 수신 레시피 검증, 실행 복사본, 포인트 순회, 진행·결과 관리 | 원본 파일 편집은 HMI, 실제 검사는 Sequence |
| Sequence | Main이 실행권을 갖고 Inspection과 Home Return을 호출 | 단일 모션 Worker, 판정은 별도 Queue Worker |
| 검사측 HMI | 모든 HMI 요청 수신과 상태·결과 송신 | HMI 화면 코드와 별개 |

실행 노드는 component를 구성해 가져다 쓴다. 반복 connect나 중복 실행 레시피 클래스를 만들지 않는다. raw 통신은 각 장비 영역, 단계 순서와 검사 정책은 Sequence가 담당한다. 독립 RobotState 노드는 제거했고 Robot/RG2의 비동기 상태를 HMI가 합쳐 발행한다.

## 3. 사용자 결정과 마지막 운영 기준

| 논점 | 논의의 결론 |

| 접근과 진입 | Ready→Entry pose는 접근(approach), 그 자리에서 Soft Grip하며 케이블 방향으로 움직이는 것이 진입(entry) |

## 4. 구현 상태와 남은 확인

[변경추적 문서](../v4/01_commons/02_변경추적_및_확인항목_v4.md)에서 합의, 현재 구현, 미결정 항목을 구분한다.

- U01 완료: 사용자 승인으로 수동 HOME도 현재 Work Access 도달을 직접 확인하고, 도달한 경우 설정 Home 경로로 바로 이동한다. 호출측 확인 플래그는 제거했다.
- U02 완료: 사용자 승인으로 Entry 접근의 `allow_incomplete=True`를 제거했다. Ready/Entry 도달 확인 후만 검사하며 접근 실패 시 정지·오류를 기록하고 후속 파지를 차단한다. 접촉 Entry/Pull의 미도달 처리 정책은 유지한다.
- R01~R05: 실제 Tool 방향, 25 mm 해제, 30 mm 후퇴·간섭, 파지 조건, 판정 임계값 검증은 실물 확인 대상이다.
- 초기 BRD의 Micro-Wiggle/Fine Alignment, 독립 connector axis, MISSING/DETACHED 확정 판정, DB 저장 확인 등은 현 구현의 보장 기능으로 적지 않았다. 삭제 합의가 있었다고 추정하지 않고 범위 검토 항목으로 이관했다.

재점검 상세: [구현 상태 재점검](../v4/03_inspection/03_verification/03_구현상태_재점검_v4.md). U03의 방향 계산·고정거리 Escape는 이미 정리된 정책으로, 추가 확장 기능·HMI 공동 책임·실물 검증과 분리했다.
