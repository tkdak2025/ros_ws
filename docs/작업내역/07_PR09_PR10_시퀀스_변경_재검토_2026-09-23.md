# 07. PR #9 → #10 시퀀스 변경 재검토

> 후속 복원 완료: 이 문서는 당시 변경/검토 기록이다. 현재 적용 정책은 [08 복원 결과](08_PR09_운영정책_복원결과_2026-09-23.md)를 따른다.
비교: PR #9 head 9156cf5 → PR #10 head 3165797. 이후 미사용 API 정리는 별도 로컬 변경이다.
사용자 최신 결정: Ready → Entry는 MoveJ. 이번에 코드·활성 설계·테스트를 수정했다. Entry 도달 확인은 유지한다. 그 외 동작은 이번 재검토에서 추가 변경하지 않았다.

## 실제 제어·판단 변경

| 항목 | PR #9 | PR #10 및 현재 | 근거/재검토 사항 |
|---|---|---|---|
| Entry 이동 | MoveJ, allow_incomplete=True | PR #10 MoveL → 이번에 MoveJ 복원 | 사용자 MoveJ 확정 |
| Entry 도달 | 미도달 허용 옵션 | TARGET_REACHED 필수, 실패 시 파지 차단 | 이동 종류와 별개 정책. 현재 유지, 재검토 대상 |
| 작업영역 내부 Home | Access → Home | 25 mm Open → Tool −Z 30 mm → Access → Home | 사용자와 구체화한 복귀 절차 |
| Open 완료 | relax 함수는 idle 대기, Home에서 미호출 | idle + 유한한 실측 폭 + 목표 ±2.5 mm 확인 | Open 확인 강화. 실제 케이블 해제 센서 판정은 아님 |
| Escape | 미호출 함수는 work_area 경계 탈출거리 계산 | 고정 30 mm 후퇴, TARGET_REACHED 확인, 경계 밖 조건 제거 | 사용자 후속 합의. 거리 실물 확인 필요 |
| Home 경로 설정 | home_pose 직접 이동 | safe_home_route 필수, 현재 [home_pose] | 실제 경유점 추가 없음. 필수 설정 도입 자체는 재검토 대상 |
| Home 관절 검사 | 설정은 전체 0도 강제, 도달 오차 0.1도 고정 | 목표 관절각 대비 설정 허용오차 검사 | 현재 목표는 여전히 전체 0도, 오차 0.1도. 비영점 설정도 허용하도록 검증이 일반화된 점은 재검토 대상 |
| Tool 접근축 | null 허용 | 유효한 벡터 필수, [0,0,1] 설정 | Tool −Z 후퇴 구현에 필요 |
| Escape 설정 | escape_clearance_mm 필수 | clearance 제거, max_escape_distance_mm을 후퇴거리로 사용 | 기존 키 유지, 양수·30 mm 이하 검증 |
| Entry/Pull 제한 | Entry 거리만 25 mm 상한 | Pull 거리도 25 mm, Entry/Pull 시간도 10초 상한 | 설계 수치 적용으로 레시피 허용 범위 축소. 재검토 대상 |
| Work Finish | motion SUCCESS, 결과 enum, 로그 저장 검사 | motion/adaptive_grip/pull SUCCESS + judgment COMPLETED + PASS/FAIL + 로그 저장 필수 | SYSTEM_ERROR/ERROR/INCOMPLETE/PENDING은 정상완료·최종 자동 Home 차단. 재검토 대상 |
| 판정 결과 반영 | 결과/판정 상태 갱신 | 판정 응답 sequence_status 실패도 pull_status에 반영 | 완료 게이트로 실패 전파 |
| PAUSED 상태 | 루프 중 별도 주기 operability 확인 없음 | 진입 및 약 1초마다 로봇 운전 가능 상태 확인 | 장비 오류를 상위 ERROR로 전달. 재검토 대상 |

SYSTEM_ERROR 등 완료 조건 미충족 시 Work Access에서 결과를 기다리고, 대기 만료 시 PAUSE한다. 모든 오류가 동일하게 즉시 PAUSE되는 것은 아니다.

## 기록·오류 처리 변경

- Job 준비를 try 안으로 이동: 폴더·판정 클라이언트 생성 실패를 처리하고 모션 시작을 차단한다.
- 생성 도중 실패 시 stream을 닫고 이전 stream으로 복원한다.
- 기록·클라이언트 close 실패에도 나머지 자원을 정리한다. 기록 실패는 RECORDING_ERROR/ERROR다.
- 정상/오류 판정의 force_data_id에 samples.jsonl 절대경로를 넣는다. HMI 파일 전송 기능은 아니다.
- 검사 종료시각과 최종 Job 종료시각을 분리하고, 최종 Home 및 기록 정리 후 COMPLETED/ERROR/STOPPED를 기록한다.
- STOP 당시 context를 최종 status 갱신에서 보존한다. 실패 기록 자체가 실패해도 context 정리를 수행한다.
- Home 시작 시 TCP 길이 6 및 유한값을 확인한다. Escape에서도 TCP·축·거리 유효성을 확인한다.

## 기존 구현 유지, 설계만 갱신한 항목

- StartInspection 전체 레시피/request_id/snapshot과 노드 역할 분리.
- Entry ABC 기반 Tool +Z 검사축과 반대 방향 Pull.
- Soft 종료 폭 기준, Pull 최소 폭 16 mm 미만 FAIL_GRIP_WIDTH. 옛 Hard 기준/MISSING으로 되돌리지 않음.
- LAN Pull 15 N, 레시피별 속도·힘 사용.
- Pull 이후 Open → Entry 직선 복귀 → Ready 이동은 이번 Entry 진입 MoveJ 수정과 별개로 유지.
