# 가상 모드 모션 및 실물 피드백 검증 (2026-09-25)

## 목적과 범위

실물 M0609/RG2 연결 없이 로컬 DRCF 가상 컨트롤러로 BMW 검사 시퀀스의 모션·단계 전이를 실행했다. 별도로 2026-09-23 HARNESS_02 실물 로그의 그리퍼 폭·Busy·시간을 현재 Soft Grip 완료 코드에 재생했다. HMI는 사용하거나 변경하지 않았고 terminal 제어를 사용했다.

## 실행 방법

각 터미널에서 `ros_ws`로 이동한 뒤 ROS 환경을 로드하고 동일한 DDS 도메인을 사용한다. 아래의 `151`은 이번 검증에 사용한 예시이며 ROS_DOMAIN_ID는 Fast DDS 범위(0~232) 안에서 다른 실행과 충돌하지 않는 값으로 정한다.

```bash
source /opt/ros/jazzy/setup.bash
source /home/rokey/ws_cobot_pjt/ws_dsr/install/local_setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=151 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

1. 가상 로봇 및 가상 그리퍼: `ros2 launch m0609_rg2_bringup bringup.launch.py mode:=virtual host:=127.0.0.1`
2. 검사 노드: `ros2 launch cable_inspection inspection.launch.py robot_mode:=virtual control_mode:=terminal results_dir:=/tmp/cccis_virtual_run`
3. 제어 콘솔: `ros2 run cable_inspection sequence_console` 실행 후 `1` 입력으로 START, `7`로 상태 확인. Job 종료 후 `q`로 콘솔을 닫고 두 launch를 종료한다.

가상 제어기는 TCP·Tool 생성에 Manual 모드를 요구한다. 검사 코드는 가상 설정 시 Manual로 전환해 등록한 뒤 Autonomous로 복귀한다. MoveJ는 가상 환경에서 실제 관절 도달(각 축 0.1° 이내)로 완료를 확인하고, 교시 TASK와의 오차를 이동 결과에 남긴다. 실물 모드의 TASK 기준 완료 판정은 변경하지 않았다.

## 이번 실행 결과

- 최종 산출물: `/tmp/cccis_virtual_run/20260925_090025_841992/` (임시 경로). `status.json`은 `completed=true`, `state=SYSTEM_READY`, `error=null`이고 `job_summary.json`은 `INSPECTION_COMPLETE`, 3/3 포인트 기록을 확인했다.
- 시작 위치가 Work Access 내부였으므로 그리퍼를 25 mm로 Open하고 현재 Tool 자세의 접근 반대방향으로 30 mm 후퇴한 다음 Work Access와 Home으로 이동했다. 세 포인트의 Ready→Entry 접근 MoveJ, Tool +Z 5 mm 진입 MoveL, Tool −Z Pull 최대 25 mm, Entry/Ready 복귀, 종료 Work Access→Home이 실행됐다. Tool 축 이동은 케이블 파지 안정화와 밀집 배선 간섭 회피를 위한 절차다. 마지막 Home TCP는 가상 제어기 기준 약 `[0, 6.25, 1243, 0, 0, 0]`이었다.
- 세 포인트 모두 시퀀스 `SUCCESS`, 판정 `FAIL(MAX_DISTANCE)`이다. 가상 환경에 케이블 접촉 저항이 없어서 Pull 힘은 약 0.12~0.16 N에 그쳤고 15 N 기준에 도달하지 않았다. 이는 가상 실행의 예상 결과이며 실물 케이블의 합격/불합격 판정 근거는 아니다.
- 가상 MoveJ의 완료 시 교시 TASK 위치 오차는 포인트 접근에서 약 0.87~1.32 mm였다. 가상 FK와 실물 교시 좌표 차이를 관절 도달 판정으로 분리했고, 실물의 0.5 mm 위치 허용오차를 완화하지 않았다.

## 실물 피드백 재현

`results/inspection_sequence/20260923_214543_195635/samples.jsonl`의 HARNESS_02 Soft Grip 구간에서 명령 이후 394개 샘플이 모두 `gripper_busy=true`였고 마지막 실측 폭은 약 24.9 mm였다. 이 구간의 시간을 당시 Busy 대기 코드에 재생하자 약 20.04초에 `GripCompletionTimeout(Soft)`이 발생했다. 기존 복구 경로 테스트 14개는 타임아웃 뒤 Open·Entry·Ready 복귀와 다음 포인트 진행, 복구 실패 시 중단을 검증하며 모두 통과했다. 검사 패키지 전체 테스트는 `163 passed, 1 skipped`였다.

같은 실물 실행의 HARNESS_01 기록(최대 Pull 힘 20.74 N, 이동량 1.566 mm, Soft 폭 23.8 mm, Pull 최소 폭 22.3 mm, 힘 제한 종료)을 현재 `judge_pull()`에 재입력해 `PASS_FORCE_DISPLACEMENT_OK`/`PASS`가 당시 결과와 일치함을 확인했다.

가상 그리퍼는 폭/관절각 이동만 제공하고 Busy·파지력·케이블 저항을 실물처럼 발생시키지 않는다. 따라서 가상 전체 Job의 성공은 모션 서비스와 단계 전이를 검증한 것이며, 실물 Busy 해제 시점, 접촉 충돌 여유, 30 mm Safe Escape의 물리적 적절성은 실물 시험에서 확인해야 한다. 위 과거 실물 로그 재생은 당시 그리퍼 대기 판정과 오프라인 복구 정책을 검증한 것이며 ROS 전체 Job에 실물 센서 스트림을 주입한 시험은 아니다.

## 이후 변경 (2026-09-25)

이 문서의 Soft Busy 타임아웃 재생은 당시 코드의 관찰 결과다. 사용자 결정으로 `gripper_busy`는 현재 제어 조건에서 제거하고 기록용으로만 유지한다. Soft 폭은 Entry 종료 직후 새 샘플로 읽고, Hard 완료는 목표 폭 또는 1.5초 폭 안정화로 판정한다. 따라서 위 과거 타임아웃 재생 결과를 현행 동작으로 해석하지 않는다.
