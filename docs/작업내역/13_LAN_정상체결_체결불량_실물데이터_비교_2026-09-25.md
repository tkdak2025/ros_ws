# LAN 정상 체결·반체결 실물 데이터 비교 (2026-09-25)

## 원본과 비교 조건

정상 체결 원본은 프로젝트 루트 `results/inspection_sequence/정상체결(2개)/`, 사용자가 체결 불량(half coupled)으로 표시한 원본은 `results/inspection_sequence/체결불량(half coupled)/`이다. 두 실행은 같은 `CCCIS_LAN_INSPECTION_V1` 레시피를 사용했고 Pull 기준은 15 N, 정상 변위 한계는 5 mm, 최대 이동거리는 25 mm다. 불량 파일에는 LAN_L5 한 포인트만 기록됐으므로 같은 포인트의 정상 기록과 직접 비교한다.

| LAN_L5 | 정상 체결 | 체결 불량(half coupled) |
|---|---:|---:|
| Entry 종료 | 힘 제한, 4.091 mm | 힘 제한, 2.767 mm |
| Hard 실측 폭 | 18.4 mm | 18.6 mm |
| Pull 중 최소 폭 | 18.2 mm | 18.6 mm |
| 최대 Pull 힘 | 18.716 N | 10.017 N |
| Pull 이동량 | 3.049 mm | 25.037 mm |
| Pull 종료 | 힘 제한 | 최대 거리 |
| 현재 판정 함수 재생 | `PASS_FORCE_DISPLACEMENT_OK` / PASS | `FAIL_MAX_DISTANCE` / FAIL |

정상 케이블은 약 3 mm 후퇴 시 15 N을 넘어 힘 제한으로 정지했다. 반체결 케이블은 최대거리 약 25 mm까지 이동했지만 15 N에 도달하지 않았다. 이 두 기록에서 체결 상태를 구분하는 직접적인 근거는 Hard Grip Busy 값이 아니라 Pull 힘·변위·종료 사유다.

## 저장 결과의 제한

반체결 실행의 옛 `inspection_results.json`에는 LAN_L5의 최대거리 종료와 실측값이 남아 있으나 `judgment_status=PENDING`, `result=null`이다. `status.json`은 `Inspection Judgment 완료 시간 초과: LAN_L5`로 미완료를 기록했고 `judgment_results.json`은 없다. 따라서 당시 시스템이 FAIL 결과를 끝까지 저장했다고 주장할 수 없다. 위 FAIL은 저장된 실측값(Soft 폭 21.9 mm, Pull 최소 폭 18.6 mm 포함)을 현재 `judge_pull()`에 재생해 얻은 결과다. 현행 ROS 전체 Job에서 이 데이터 스트림을 주입한 시험은 별도로 하지 않았다.

기존 형식의 `samples.jsonl`은 포인트 ID와 원시 RG2 상태 비트 `gsta`를 저장하지 않는다. `gripper_busy`는 드라이버가 상태 비트필드 전체를 단일 불리언처럼 전파한 값이라 파지 감지와 실제 동작 중 상태를 구별할 수 없다. 반체결 Hard Grip은 폭 18.6 mm에서 `gripper_busy=false`가 관측됐고, 정상 기록은 폭 18.4 mm에서 `true`가 유지됐지만 이 차이만으로 체결 품질을 판정하지 않는다.

## Entry/Pull 샘플 구분

이전 형식의 원본 샘플에도 Entry 구간은 `entry_displacement_mm`, Pull 구간은 `pull_force_n`과 `pull_displacement_mm`가 기록되어 있다. 현재 형식에는 `measurement_kind`도 추가된다. `gripper_busy`는 어느 구간의 종료나 다음 동작 허용 조건에도 사용하지 않는다.
