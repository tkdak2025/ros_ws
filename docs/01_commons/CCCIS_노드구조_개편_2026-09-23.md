# CCCIS 검사 노드 구조와 실행 가이드

기준: 2026-09-25. `cable_pkg` 및 중간 패키지명 `cable_management`를 `cable_inspection`으로 대체했습니다.
현재 구현과 상세 인터페이스는 [cable_inspection README](../../src/cable_inspection/README.md)를 따릅니다.

## 책임 범위

| 패키지 | 담당 |
|---|---|
| cable_inspection | 실제 로봇·그리퍼 제어, 검사 실행·판정, 상태·결과 발행 |
| cable_interfaces | 두 PC가 공유하는 메시지·서비스 타입 |
| cable_hmi | HMI 담당: 화면, 검사 레시피 원본 관리, 결과 이력 관리 |

검사 패키지에 HMI 화면이나 레시피/결과 DB·목록·저장·조회 노드는 없습니다.
HMI 통신 노드가 StartInspection 서비스로 검사 레시피를 접수하고 Main 노드가 작업 가능 상태를 확인합니다. 레시피 해석·검증·보관은 Recipe 노드에 위임하고 실행 배열은 Recipe가 Job 시작 시 고정합니다. Main은 다음 포인트를 요청해 검사하고 결과를 Recipe에 반영합니다.
시스템 레시피·장비 설정과 측정 진단용 로컬 파일 기록은 검사파트가 관리합니다.
공통 패키지에 있는 관리용 서비스 타입은 검사 패키지가 해당 서버를 제공한다는 뜻이 아닙니다.

## 실행 노드와 소스 위치

소스 기준 경로는 `src/cable_inspection/cable_inspection/`입니다.

| 실행 항목 | ROS 노드 | 소스 | 역할 |
|---|---|---|---|
| main_sequence | ccc_sequence_node | sequence/main/node_main.py | #00·#01·#07 실행권, 명령 실행 판단·Worker 수명 |
| main_sequence 내부 | ccc_hmi_node | hmi/node_hmi.py, hmi/interface.py | 모든 외부 HMI 서비스·명령·Heartbeat·상태·결과·로그 통신 |
| main_sequence 내부 | ccc_recipe_node | recipe/node_recipe.py | 레시피 해석·검증·보관·순회·현황 API, 같은 프로세스에서 호출 |
| main_sequence 내부 | ccc_inspection_node | sequence/inspection/node_inspection.py | #06 비동기 판정 |
| main_sequence 내부 | ccc_robot_node | robot/node_robot.py, robot/m0609.py | M0609 component 상속·로봇 API |
| main_sequence 내부 | ccc_gripper_tool_node | gripper_tool/node_gripper_tool.py, gripper_tool/rg2.py | 독립 RG2 component 상속·그리퍼 API |

#02 Home Return과 #03~#05 Inspection은 ROS 노드가 아니라 Main의 한 Worker에서 순서대로 호출하는 시퀀스다. Main 노드는 두 시퀀스를 import해 조립하므로 모션이 동시에 실행되지 않는다. 검사 레시피 접수·Snapshot 발행은 HMI 노드가 담당하고 Main은 실행 허용 여부를 판단한다.

`robot/m0609.py`와 `gripper_tool/rg2.py`가 각각 통신·raw 명령을 담당하고, 각 폴더의 `node_대상.py`가 이를 상속해 API를 제공한다. 두 장비 노드는 서로 참조하지 않으며 Main이 생성해 Sequence에 전달한다. Main 시퀀스가 HMI 연결과 레시피 선택을 판단한다. Main 소유 `sequence/common/motion.py`는 같은 연결 위에서 계측·모션 완료를 확인하고, `sequence/home_return/seq_home_return.py`는 Safe Escape·Home 경로와 도달 검증을, `sequence/inspection/seq_inspection.py`는 검사 절차를 담당한다. 레시피 component는 `recipe/recipe.py`, Recipe 노드·메시지 변환은 `recipe/node_recipe.py`, 자세 오차·탈출 방향 계산은 `sequence/common/geometry.py`, 공통 운전 설정과 결과 모델은 `sequence/*/data_models/의 개별 정의 파일`, 작업영역 계산은 `safety/workspace_boundary.py`에 있다.

## 검사 PC 실행

로봇/RG2 드라이버는 기존 sodreal 또는 별도 driver launch로 먼저 실행합니다.
프로젝트의 ros_ws 디렉터리에서 다음을 실행합니다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/ws_cobot_pjt/ws_dsr/install/local_setup.bash
colcon build --symlink-install --packages-select cable_interfaces cable_inspection
source install/local_setup.bash
ros2 launch cable_inspection inspection.launch.py control_mode:=hmi robot_mode:=real
```

이 launch는 Main·판정 노드가 있는 검사 프로세스와 읽기 전용 상태 프로세스를 실행하고 START를 기다립니다.
HMI 프로그램은 별도로 실행합니다. 유효 HMI heartbeat와 전체 검사 레시피를 포함한 StartInspection 요청이 필요합니다.
터미널 운전은 control_mode:=terminal로 실행하고, 별도 터미널에서 `ros2 run cable_inspection sequence_console`을 실행합니다.

## 검사 통신

패키지명 변경 후에도 `/cable_inspection/...` 주소와 메시지/서비스 타입은 유지합니다.

| 주소 | 타입·용도 |
|---|---|
| /cable_inspection/start | StartInspection: request_id와 InspectionRecipe 전체 접수 |
| /cable_inspection/command | String JSON: PAUSE, RESUME, STOP, HOME_RETURN, SYNC |
| /cable_inspection/hmi_heartbeat | Empty: 제어 연결 감시 |
| /cable_inspection/robot_status | String JSON: 상시 로봇상태 |
| /cable_inspection/work_status | String JSON: 작업상태; 작업 중 주기 발행, 대기는 변경/SYNC 응답 |
| /cable_inspection/execution_snapshot | String JSON: 실행 레시피 복사본 |
| /cable_inspection/judgment_result | InspectionResult: 포인트별 판정 |
| /cable_inspection/log | String JSON: 실행 로그 |

검사 레시피의 points는 실행 순서대로 보내는 구조화 배열이며 애플리케이션 상한은 1000개입니다.
시스템 레시피/Home/Tool 설정은 HMI가 보내는 검사 레시피에 포함하지 않습니다.
START accepted는 접수 성공이며 장비 초기화·검사 완료를 의미하지 않습니다.
같은 request_id와 같은 레시피의 재전송은 기존 run_id를 반환하며 재실행하지 않습니다.
접수 이력은 현재 Main 프로세스 수명 동안 유지됩니다. 상세 거절코드는 패키지 README에 있습니다.

수동 HOME은 이전 검사 request_id를 비웁니다. 검사 내부 자동 HOME은 검사 ID를 유지합니다.
robot_status와 work_status의 수집/발행 주기는 독립적입니다.

## 검증

- cable_inspection와 cable_interfaces만 포함한 독립 워크스페이스에서 일반 설치 빌드 성공.
- 검사 회귀 테스트 167개와 격리 ROS launch/서비스 통합시험 1개 통과.
- 이전 cable_pkg/cable_management 없이 Main·판정·로봇 상태 노드 기동·통신 확인.
- 실물 이동 명령과 실물 전체 검사 시험은 수행하지 않았습니다.
- HMI 화면·통신 구현 변경은 별도 담당 범위로 분리합니다.

HMI 화면 코드는 변경하지 않는다. 기존 외부 서비스·토픽·QoS는 유지하며, 판정 노드는 결과를 HMI 노드 콜백으로 전달한다. 읽기 전용 상태 수집 노드는 내부 토픽만 발행하고 HMI 노드가 기존 robot_status로 전달한다. 실행 방법은 기존 inspection.launch.py와 동일하다.

2026-09-25 상태 수집 이관: RobotNode·GripperToolNode가 장비별 상태·유효성을 관리하고 HmiNode가 기존 외부 상태를 발행한다. Main executor가 모든 ROS 콜백을 처리하며 시퀀스 Worker는 응답을 기다릴 뿐 spin하지 않는다. 별도 상태 노드와 내부 중계 토픽은 제거했다.
