# CCCIS Business Requirements Document v4

버전: v4 · 기준일: 2026-09-25 · 범위: 검사파트와 HMI 통신 계약

[v4 문서 안내](../00_문서안내_v4.md) · [변경 근거·확인 항목](02_변경추적_및_확인항목_v4.md)

## 1. 목적과 업무 문제

M0609 로봇과 RG2로 사전에 등록된 케이블 검사포인트를 파지·인장하고, 힘·변위·파지 폭을 기록하여 체결상태 판정 근거를 제공한다. 작업자가 관리한 교시 자세와 레시피를 반복 실행하며, 정상/불량 결과와 시스템 오류를 구분한다. 검사 조건을 실행별로 추적할 수 있어야 한다.

비전 없는 알려진 작업 환경을 전제로 한다. 배선의 실제 위치 편차와 접촉 저항은 실측값으로 관찰한다. 미등록 케이블의 자동 인식, 전기적 도통 검사, 자동 재체결·수리는 이번 구현의 제공 기능이 아니다.

## 2. 담당 범위

| 담당 | 업무 |
|---|---|
| HMI 파트 | 원본 레시피 파일·버전·UI·작업자 명령·결과 DB 관리 |
| 검사 파트 | 장비 연결, 수신 레시피 실행, 순회, 계측, 판정, 실행 기록, 상태·결과 통신 |
| 공동 인터페이스 | cable_interfaces의 ROS2 메시지·서비스 계약과 ID 대응 |

이 BRD를 갱신하면서 HMI 화면 코드를 변경하지 않는다. 원본 레시피를 HMI가 관리하고 검사 측은 통신으로 받은 실행 복사본을 사용한다.

## 3. 운영 시나리오

1. 장비와 검사 노드를 기동한다. 기동 자체로 검사 모션을 시작하지 않는다.
2. HMI가 heartbeat와 함께 전체 Recipe를 START 서비스에 전달한다. terminal 운전에서는 등록 JSON 파일을 입력으로 사용한다.
3. Main은 장비·모드·Tool/TCP·레시피를 점검하고 Work Access를 확보한다. Home에서의 시작을 강제하지 않는다.
4. Recipe가 활성 포인트를 배열 순서대로 제공한다. 접근→Soft Grip/진입→Hard Grip→Pull→해제/복귀를 실행한다.
5. Pull 직후 비동기 판정을 요청하고 모션은 다음 단계로 진행한다.
6. 마지막 포인트 뒤 Work Access에 복귀하고 모든 결과·기록을 확인한 뒤 SYSTEM_READY로 대기한다. Home은 별도 명령이다.

## 5. 품질·데이터 요구사항

- 위치 mm, 관절·ZYZ 자세 deg, 힘 N, 시간 s로 단위를 명시한다. 유효하지 않거나 오래된 피드백을 정상값으로 위장하지 않는다.
- 결과 판정과 모션/Job 완료를 구분한다. FAIL을 포함한 Job도 검사 절차와 기록이 완료될 수 있다.
- HMI DB 저장과 검사 측 로컬 저장은 별개다. 현재 DB 저장 완료 ACK를 보장하지 않는다.
- 동시 START/HOME 및 정리 중 새 실행은 거절한다. STOP 시 새 작업을 실행하기 전에 이전 Worker와 문맥을 정리한다.
- 명확한 메서드 이름, 기능·인자·반환 주석, 기능별 블록 간격을 적용한다. 코드 스타일의 전 항목 준수를 문서 작성만으로 인증하지 않는다.

## 6. 이번 기준의 한계와 범위 이관

초기 BRD의 Micro-Wiggle·Fine Alignment·Grip Stability 세부 확장, 별도 connector axis, MISSING/DETACHED 분류, 힘 유지 검사, 자동 CSV/DB 연동 완료 확인은 현재 구현과 일치하지 않거나 추가 요구 정의가 필요하다. 기능 삭제가 승인된 것으로 간주하지 않는다. [변경추적 및 범위 검토](02_변경추적_및_확인항목_v4.md)의 U03에서 원래 요구와 현 기능의 차이를 남긴다.

30 mm Escape는 설정 거리 후퇴이며 작업영역 이탈이나 무간섭 경로를 수학적으로 보장하지 않는다. 그리퍼 폭 16 mm 판정 임계값도 전 제품에 검증된 기준으로 단정하지 않는다.
