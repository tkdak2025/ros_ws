# Concept 06 — 비동기 판정

버전: v4 · 기준일: 2026-09-25 · 범위: 검사파트와 HMI 통신 계약

[v4 문서 안내](../../00_문서안내_v4.md) · [변경 근거·확인 항목](../../01_commons/02_변경추적_및_확인항목_v4.md)

## 책임

InspectionJudgmentNode는 측정 요청 Queue, Worker, 판정 함수, 결과 보관을 직접 소유한다. 별도 JudgmentClient와 판단 전용 파일을 거쳐 같은 책임을 중복 분산하지 않는다. 외부 ROS 요청·결과 발행은 HmiNode가 담당하고, 내부 모션에서의 요청은 같은 Queue API에 넣는다.

## 수명과 결과 일관성

실행 시작에 run_id와 판정 세대를 갱신한다. 이전 실행의 늦은 결과, 같은 run_id/point_id의 중복 요청은 현재 실행 결과를 덮지 못하게 처리한다. 복귀 오류로 확정한 오류 결과도 늦게 도착한 정상 판정으로 바꾸지 않는다.

Recipe는 pending과 포인트별 결과를 관리한다. Main은 결과 복사본을 수집·저장하고 최종 완료 여부를 확인한다. 판정 지연은 즉시 다음 모션을 막지 않지만 Job 완료를 지연시킨다.

## 외부 표출

PASS/FAIL/SYSTEM_ERROR와 reason_code/reason을 구분하여 보낸다. 유효하지 않은 수치가 메시지상 0으로 직렬화되어도 오류 결과를 정상 0 측정으로 해석하지 않는다. db_saved=false는 HMI DB 저장 완료를 알 수 없다는 현재 상태다.

디버그용 `inspection_judgment` 단독 실행 진입점은 유지한다. 전체 실행과 같은 도메인에서 중복 결과 발행자로 사용하지 않고 분리된 시험 환경에서 쓴다.

판정 조건과 비교 우선순위는 [#06 상세 설계](../02_sequences/06_Inspection_Judgment_Sequence_v4.md) 하나를 기준으로 한다. 검증은 E01~E05 및 G02를 연결한다.
