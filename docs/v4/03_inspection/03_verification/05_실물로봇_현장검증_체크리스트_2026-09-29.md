# HMI 연동 실물 로봇 2회 검증 체크리스트

> 이 문서의 날짜별 수치·경로·시험 기록은 당시 이력이다. 현재 HOME/그리퍼/레시피 기준은 [최신 변경 요약](04_운영코드_반영_검증요약_v4.md#2026-09-30-현행-변경과-회귀검증), [HOME 시퀀스](../02_sequences/02_Home_Return_Sequence_v4.md), [Recipe](../01_concepts/04_Recipe_컨셉_v4.md)를 따른다. 과거 체크 결과를 변경된 경로의 실물 검증 완료로 승계하지 않는다.


작성일: 2026-09-29 · 대상: M0609 / OnRobot RG2 / cable_inspection

HMI와 실물 로봇을 연동하여 설계·의도와 실제 동작이 일치하는지 두 차례 확인하는 시험표다. 1차는 기존 체크리스트를 기준으로 Codex에 검증 문서 작성과 결과 정리를 맡기고, 2차는 사용자가 직접 검증한다. Codex는 관측 자료 없이 실물 동작을 확인했다고 기록하지 않는다. 모든 항목은 미실행 상태로 시작한다. 자동시험 통과 이력은 실물 시험 결과로 대신하지 않는다.

기준 문서: [기능 검증 체크리스트](01_기능검증_체크리스트_v4.md), [실행 가이드](02_실행과_정량검증_가이드_v4.md), [시스템 설정](../../../../src/cable_inspection/config/system_recipe.json).

HMI 추가 항목 출처: [HMI 파트 추가 체크리스트](05_실물로봇_현장검증_체크리스트_2026-09-29%232.md). 기존 2회 검증 방식을 유지하고 P10·HM01~HM20 및 알려진 한계를 통합했다.

## 0. 두 회차의 진행 원칙

| 구분 | 1차 검증 | 2차 검증 |
|---|---|---|
| 작성·확인 역할 | 기존 체크리스트에 따라 Codex가 시험 항목·기대 동작·제공된 관측 결과 정리 | 사용자가 직접 조작·관찰하고 결과 작성 |
| 실행 환경 | HMI + 검사 프로그램 + 실물 M0609/RG2 | 동일한 HMI 연동 환경 |
| 확인 목표 | 설계·의도와 실제 동작의 차이 및 누락 식별 | 설계대로 동작하는지 직접 재확인하고 수정 사항 재검증 |

두 회차 모두 아래 전체 항목을 대상으로 한다. 1차 통과를 이유로 2차 항목을 자동 통과 처리하지 않는다. HMI 버튼 입력 → 서비스 접수 → 로봇·그리퍼 동작 → 상태·판정·파일 기록이 의도한 흐름으로 이어지는지 확인한다. 문서와 코드가 다르면 코드 동작만을 근거로 통과 처리하지 않고 설계 불일치로 남긴다.

각 회차 시작 시 코드·HMI 버전, 레시피, 시스템 설정을 기록한다. 회차 사이 수정이 있으면 변경 내용과 영향을 받는 항목을 기록한다. 운전 명령은 HMI로 입력하며 직접 서비스 호출 시험은 별도 보조 시험으로 표시한다.

## 7. HMI 연동 — 두 회차 모두 필수

- [ ] H01 — START accepted는 접수로 표시하며 완료로 표시하지 않는다. run_id와 Snapshot이 실행과 일치한다.
- [ ] H02 — 같은 request_id·같은 레시피 재전송은 ALREADY_ACCEPTED이며 재실행하지 않는다.
- [ ] H03 — 같은 request_id·다른 레시피는 REQUEST_ID_CONFLICT이며 현재 실행을 변경하지 않는다.
- [ ] H04 — 활성 포인트·진행률·PAUSED/STOPPED/ERROR/SYSTEM_READY·판정이 실제 상태와 일치한다.
- [ ] H05 — 연결 유실이나 만료된 값이 정상 최신값으로 표시되지 않는다.

- [ ] H06 — HMI의 START/PAUSE/RESUME/STOP/HOME 입력과 실제 동작·상태 전이가 일치한다. 버튼 미제공·비활성으로 시험할 수 없으면 연동 제약으로 기록한다.
- [ ] H07 — STOPPED/ERROR에서 원인 해소 후 새 START가 가능한 설계와 HMI 버튼 활성 조건이 일치한다.
- [ ] H08 — 완료 시 로봇은 Work Access에 대기하고 HMI는 판정·저장 완료를 확인한 뒤 완료 상태를 표시한다.
- [ ] H09 — HMI에서 선택한 레시피·버전·포인트 순서·활성 여부·조건이 execution_snapshot 및 실제 실행과 일치한다.
- [ ] H10 — PASS/FAIL/SYSTEM_ERROR 및 사유가 HMI와 파일에서 일치하며 접수 성공·작업 완료·제품 합격을 구분한다.

### 7-1. HMI 화면 확인 (cable_hmi)


HM01~HM20은 두 회차 모두 기록한다. 기존 H01~H10은 연동 계약의 공통 기준이며 아래 HM 항목은 화면·저장·복구의 세부 확인이다. 위 시험을 진행하면서 HMI 화면을 함께 관찰한다. '대조' 열의 시험과 같은 시점에 기록한다. 화면 값은 로봇 TP·실물·검사 PC 로그와 비교하며, HMI 표시만으로 동작 성공을 판단하지 않는다.

- HMI의 STOP 버튼은 작업 정지 명령(`STOP`)이다. 하드웨어 비상정지를 대신하지 않으므로 P01의 비상정지 담당은 그대로 둔다.
- HMI는 execution_snapshot을 화면에 표시하지 않는다. H01의 Snapshot 대조는 `ros2 topic echo /cable_inspection/execution_snapshot --once`나 검사 PC의 inputs.json으로 확인한다.

### 7-2. 알려진 HMI 한계 및 설계 불일치 추적

아래는 추가 문서에서 전달된 알려진 한계이며 현장 확인 완료를 뜻하지 않는다. 설계와 다른 동작·결과 유실·저장 불일치는 해당 항목에 실패 또는 미실행으로 남기고 증거를 기록한다. 문서에 알려진 한계로 기재되어 있다는 이유만으로 통과·면제하지 않는다. 미지원 범위나 표시상의 제약은 요구사항과 대조하여 해당 없음 사유를 기록한다.


- HM15/HM16 — xlsx '요약' 시트의 끝난 이유가 UNKNOWN으로 남을 수 있다. 수동 Home 뒤 직전 검사 요약 행이 덮어써질 수 있다.
- H02/H10/HM07/HM08 — HMI 결과 저장 노드가 저장 확인용으로 judgment_result를 재발행한다(v4 통신 인터페이스 문서와 불일치, 수정 예정). `ros2 topic echo`로 judgment_result를 보면 같은 결과가 `db_saved: true`로 한 번 더 보인다.
- HM19/HM20/L03 — judgment_result는 VOLATILE이다. HMI를 끈 동안 나온 결과는 HMI 표·DB·xlsx에 남지 않는다. 검사 PC 결과 폴더에는 남는다.
- HM13 — '일시정지 · 통신 단절' 표시는 검사 PC가 HMI Heartbeat를 못 받는 동안 HMI는 상태를 받고 있을 때만 보인다. 양쪽이 모두 끊기면 '통신 끊김'으로 보인다.
- 속도 조절·FAIL 포인트 이동·비상정지 해제는 검사 PC(v4)가 명령을 받지 않아 시험 대상이 아니다(HM17).
- HM18 — 시스템 로그의 시각은 HMI가 받은 시각이다(검사 PC 로그에 시각이 없음). 검사 PC 터미널 로그와 조금 어긋날 수 있다.
- HM07/HM16 — 제품 ID와 케이블 ID는 결과 메시지에 없어 '—'로 보인다.
- 검사 중에 HMI를 끄면 Heartbeat가 끊겨 검사 PC가 Safe Pause로 들어간다(C05와 같음). HMI 재시작 시험(HM20)은 대기 중에 한다.

## 12. 현장 점검 절차와 방법

이 절을 실행 순서로 사용하고, 2~10장의 체크리스트와 회차별 결과 원장에 결과를 기록한다. 명령어는 작업자가 직접 실행한다. 문서 작성만으로 어느 항목도 완료 처리하지 않는다.

### 12-1. 공통 준비와 기동 (P01~P10)

1. 시험 회차·작업자·코드/HMI 버전·시험품을 1장에 기록한다. 로봇 조작 담당과 화면·로그 기록 담당을 정하고 P01~P03을 실물로 확인한다.
2. TP에서 현재 Tool/TCP 이름·설정과 관절/작업 좌표를 확인한다. 레시피의 BASE 기준 및 교시 당시 Tool/TCP와 대조한다. 자세가 같아도 공구 기준이 다르면 시험을 진행하지 않는다.
3. 실제 사용하는 시스템 설정의 Home·Work Access·작업영역과 각 Ready/Entry를 대조한다. 끝점뿐 아니라 관절 이동 중 공구·팔·케이블 전체 경로를 확인한다. 변경된 Ready도 실물 경로 확인 전에는 충돌 검증 완료가 아니다.
4. 회차별 시험 레시피 복사본을 별도 폴더에 준비한다. 첫 시험은 대상 포인트만 enabled=true, 나머지는 false로 설정하고 별도의 recipe_id를 부여한다. 원본을 덮어쓰지 않는다. Ready/Entry 및 힘·속도·거리·시간을 적용값 표에 기록한다.
5. HMI PC가 읽는 복사본과 검사 시점 inputs.json의 레시피를 대조한다. 파일 이름만 같다고 동일한 내용으로 판단하지 않는다.
6. 드라이버 → 검사 프로그램 → HMI 순으로 기동한다. 기존 드라이버가 실행 중이면 중복 실행하지 않는다. START 전에는 정지 상태를 유지한다.

현재 원본 레시피:

| 위치 | 파일 / recipe_id |
|---|---|
| 하부·우측 | `rcp_BMW_HARNESS_LWR_RH_01.json` / `rcp_BMW_HARNESS_LWR_RH_01` |
| 상부·우측 | `rcp_BMW_HARNESS_UPR_RH_02.json` / `rcp_BMW_HARNESS_UPR_RH_02` |

상부·우측의 `LAN_MONITOR_ARM_01` Ready는 Joint `[10.05, 23.04, 103.25, 11.65, -99.93, 78.04]`, Task `[599.30, 46.16, 583.46, 165.30, -28.40, -81.92]`로 변경되었다. 시험 시 실제 파일과 Snapshot에 이 값이 반영되었는지 확인한다.

각 PC의 새 터미널에서 환경을 준비한다. 아래 작업 경로는 현재 검사 PC 기준이며 HMI가 다른 PC이면 해당 PC 경로로 바꾼다.

```bash
cd /home/rokey/Desktop/ROKEY9/ROKEY_3/PRJT_CCCIS/ros_ws
source /opt/ros/jazzy/setup.bash
# 검사 PC: 설치된 두산/RG2 underlay 환경도 source

source install/setup.bash
printenv ROS_DOMAIN_ID ROS_AUTOMATIC_DISCOVERY_RANGE
```

두 PC의 도메인 및 검색 설정이 서로 통신 가능한지 확인한다. HMI PC에 두산 underlay가 없다면 그 줄은 생략한다. 파일명 변경 후 설치본이 갱신되지 않았다면 운전 프로그램을 종료한 상태에서 해당 PC의 패키지를 빌드하고 다시 source한다.

```bash
# 세 패키지가 모두 있는 현재 워크스페이스 기준
colcon build --symlink-install --packages-select cable_interfaces cable_inspection cable_hmi
source install/setup.bash
```

검사 PC 터미널:

```bash
ros2 launch cable_inspection inspection.launch.py control_mode:=hmi robot_mode:=real
```

HMI PC 터미널:

```bash
ros2 launch cable_hmi hmi.launch.py mock:=false
```

시험 복사본을 사용할 때는 위 HMI 명령에 `inspection_recipe_dir:=/실제/시험레시피/폴더`를 붙인다. 이 경로는 HMI PC 기준이며 실제 경로로 교체해야 한다. hmi 모드에서는 검사 launch의 `recipe` 인자가 아니라 HMI가 전달한 레시피가 실행된다. 두 회차의 결과 폴더는 검사 launch의 `results_dir` 인자로 구분하거나 실행별 실제 생성 경로를 원장에 기록한다.

### 12-2. 관측 도구와 증거 수집 (S01~S05, L01~L05)

1. HMI·실물·TP가 정지 상태임을 확인한다. 연결 상태, Tool/TCP, 현재 좌표와 폭을 같은 시점에 기록한다.
2. 다음 조회 명령으로 노드·통신 경로를 확인한다. 아래 명령은 로봇 구동 명령을 보내지 않는다.

```bash
ros2 node list
ros2 service list -t
ros2 topic list -t
ros2 topic info /cable_inspection/hmi_heartbeat --verbose
ros2 topic echo /cable_inspection/robot_status --once
ros2 topic echo /cable_inspection/work_status --once
```

3. START 전에 별도 터미널에서 아래 Snapshot 조회를 실행해 기다린다. 이미 발행된 메시지는 QoS에 따라 수신되지 않을 수 있으므로 응답이 없다고 임의로 START를 반복하지 않는다. 실행 후 inputs.json으로도 확인할 수 있다.

```bash
ros2 topic echo /cable_inspection/execution_snapshot --once
```

4. 필요하면 별도 터미널에서 `ros2 topic echo /cable_inspection/log`와 `ros2 topic echo /cable_inspection/judgment_result`를 관찰한다. 연속 조회 종료는 해당 조회 터미널의 Ctrl+C로 한다.
5. 영상 또는 화면 녹화에는 조작 시각·단계·실물 동작을 대응시킨다. 증거 이름은 `회차_항목ID_runID_pointID`로 구분한다. ROS 원문, 검사 파일, HMI 표시를 같은 run_id/point_id로 대조한다.
6. 조회값이 없으면 모드·도메인·토픽·노드부터 확인한다. 값이 없는 상태를 정상값 0으로 해석하지 않는다.

### 12-3. 단일 포인트 검사 (M01~M10, H01/H04/H08~H10, HM04~HM09)

1. 검증된 작업영역 밖 시작 자세에서 단일 포인트 시험 레시피를 선택한다. HMI 목록의 ID와 실제 파일을 확인하고 녹화를 시작한다.
2. HMI의 '검사 시작'을 한 번 누른다. 접수 응답·run_id를 기록하고 실행 Snapshot의 포인트·좌표·조건을 대조한다. 응답 지연 시 다시 누르지 말고 로그를 확인한다.
3. Work Access → Open → Ready MoveJ → Entry MoveJ 순서를 실제 동작·단계 로그로 확인한다. 실측 관절/TCP와 목표값을 비교하고 도달 실패 시 후속 파지가 차단되는지 관측한다. 일부러 장애물로 막아 시험하지 않는다.
4. Entry의 자세 기준 Tool +Z와 케이블 진입 방향을 대조한다. Soft Grip → 추가 진입 → 새 폭 측정 → Hard Grip → 반대 방향 Pull 순서와 실물 파지 상태를 영상에 남긴다.
5. Pull 중 HMI 폭·힘·변위를 관찰하고 종료 시각·종료 사유를 기록한다. 파일에서 해당 포인트의 정지 요청 전후부터 정지 완료까지 샘플을 확인한다. 판정 코드가 사용하는 힘·변위 기준과 같은 기준으로 최대 힘·최소 폭을 대조하며 화면의 반올림 값만으로 판정하지 않는다.
6. Open 후 케이블이 실제로 해제되는지 확인하고 Entry MoveL → Ready MoveJ → Work Access 복귀를 관찰한다. 해제 여부가 불명확하거나 경로가 예상과 다르면 중단한다.
7. HMI 완료 표시 시점과 검사측 판정·저장 완료를 대조한다. 자동 Home이 없는지 확인하고 결과 파일 경로를 남긴다.
8. 각 포인트를 단독으로 확인한 후 다중 포인트 시험으로 넘어간다. 한 포인트 통과를 다른 자세의 포인트에 적용하지 않는다.

### 12-5. 일시정지·정지·복구 (C01~C07, H06/H07, HM11~HM14)

1. C01: 정상 동작을 확인한 단일 포인트로 시작한다. 관측할 단계에서 '일시정지'를 한 번 누르고 요청 시각과 실제 PAUSED 전환 시각을 기록한다. 원자 동작 완료 후 대기하며 다음 단계가 진행되지 않는지 확인한다. '이어하기' 후 중복 동작 없이 이어지는지 확인한다.
2. C02: 별도 실행에서 간섭 없는 이동 구간에 STOP을 누른다. 입력·정지 시작·정지 완료 시각과 최종 자세를 기록한다. 정지 후 자동 복귀·다음 포인트 이동이 없어야 한다. HMI STOP을 하드웨어 비상정지로 간주하지 않는다.
3. C03: 별도 실행을 PAUSED까지 진행한 후 STOP을 누른다. Job 종료·문맥 폐기·미완료 기록을 확인한다.
4. C04/H07: STOP 완료 후 원인을 확인하고 새 START를 입력한다. 현재 위치에 따른 Access 확보와 새 실행 식별을 확인한다. ERROR 재시작은 자연 발생 오류의 원인을 해소한 경우에만 수행하고, 오류가 없다면 모의시험으로 분리한다.
5. C07/HM14: 실행·PAUSED·정지 처리 중 각 화면을 캡처하여 START/HOME 비활성을 확인한다. 비활성 버튼을 우회해 서비스 호출하지 않는다. 서버의 동시 명령 거절 자체는 12-8의 보조 시험으로 확인한다.

### 12-6. 통신 유실과 재기동 (C05/C06, H05, HM13/HM19/HM20)

- **대기 상태 재기동부터 수행:** Job·모션이 없을 때 검사 launch 터미널에서 Ctrl+C로 종료하고 HMI의 끊김 표시·값 무효화 시각을 기록한다. 검사 프로그램을 같은 인자로 재기동하고 HMI 자동 재연결을 확인한다(HM19). 다음으로 대기 상태에서 HMI를 정상 종료·재기동하여 현재 상태와 통합 조회의 이전 결과를 확인한다(HM20).
- **C05의 HMI 종료 방식:** 정상 단일 포인트 검증 후, 간섭 없는 조건에서 HMI를 정상 종료하고 검사 PC 로그로 Heartbeat 만료·Safe Pause를 관측한다. 설정된 복구 제한시간 안에 HMI를 같은 인자로 재기동한다. 복구만으로 움직이지 않고 RESUME 입력을 기다리는지 확인한다. 제한시간을 넘겼다면 C05 통과로 기록하지 않는다.
- **C06:** 별도 실행에서 같은 방식으로 HMI를 종료한 뒤 통신 복구 제한시간을 넘겨 COMM_ERROR·Job 중단·자동 Home 없음·미완료 저장을 검사 PC에서 확인한다. 이후 HMI를 재기동하여 오류 표시를 확인한다.
- **편도 Heartbeat 유실 표시:** HMI 종료 방식은 화면을 함께 관찰할 수 없다. HMI가 상태를 계속 받는 동안의 '일시정지 · 통신 단절' 표시까지 확인하려면 Heartbeat만 중단하는 별도 시험 도구가 필요하다. 도구가 준비되지 않으면 HM13의 이 세부 조건을 미실행으로 남긴다. 종료 시험으로 대체 통과하지 않는다.
- **시간 기록:** 마지막 Heartbeat 수신, 유실 감지, PAUSED, 복구, RESUME, COMM_ERROR 시각을 구분한다. 2 s/30 s는 저장소 기준이며 실제 적용 설정과 비교한다. 전체 LAN 단절·로봇 전원 차단으로 대신하지 않는다.

| HM15 | 완료 후 결과 파일 저장 → 실제 생성 경로 기록 → 최근 파일 열기 → 화면·검사 JSON과 행별 대조. HOME 전후 요약도 비교 | xlsx/db·검사 JSON·비교 결과 |

| HM18 | 시스템 로그의 내용·순서·수준 색과 검사측 로그 비교. ERROR가 자연 발생하거나 모의 재현된 경우 누적 팝업·STOP 접근 가능 여부 확인 | 로그 캡처·대응 원문. 수신 시각 차이 별도 기록 |
| HM19/HM20 | 12-6의 대기 상태 재기동 절차 수행 | 종료·끊김·복구 시각과 이전 결과 보존 여부 |

HMI가 'DB 저장 완료'라고 표시해도 실제 DB/내보낸 결과가 일치하는지 확인한다. 제품·케이블 ID 미제공과 VOLATILE 결과 유실은 7-2의 제약과 대조하여 범위를 기록한다.

### 12-8. 보조 시험과 오류 분기 (H02/H03, HM04/HM18, C07 서버 거절, 10장)

1. 중복 요청 ID, 다른 레시피 재전송, 강제 응답 지연, 비정상 피드백은 일반 HMI 조작만으로 재현할 수 없는 항목이다. 실물 운전과 분리된 모의 환경에서 수행한다.
2. H02는 동일한 request_id·전체 레시피 요청을 두 번 보내 최초 접수와 ALREADY_ACCEPTED, 동일 run_id, Worker 실행 1회를 확인한다. H03은 그 ID를 유지하고 레시피를 변경하여 REQUEST_ID_CONFLICT와 실행본 불변을 확인한다. 실물에서 새 ID로 반복 전송해 대신하지 않는다.
3. 10장 오류는 해당 조건의 모의 입력·기대 중단 위치·실제 후속 명령 유무·오류 기록을 확인한다. 자동 보고서의 개별 시험 증거를 연결하며 전체 통과 숫자만으로 개별 항목을 완료 처리하지 않는다.
4. 자동검증 재실행이 필요하면 실물 운전 프로그램을 종료하고 가상 모션 옵션 없이 아래 명령을 사용한다. ROS 모의 통합시험을 추가할 경우 실물 운전 환경과 격리하여 별도로 수행한다.

```bash
# ros_ws에서 ROS 및 설치 환경을 source한 뒤 실행
python3 src/cable_inspection/cable_inspection/diagnostics/check_inspection.py
# 메뉴 1: 실물 장비 없는 회귀시험·정량 비교
```

5. 보고서·개별 로그를 원장에 연결하고 '모의 검증'이라고 표시한다. HMI 팝업·화면을 실제로 확인하지 않은 자동시험은 해당 UI 시험의 증거로 대신하지 않는다. 도구나 재현 조건이 없으면 미실행으로 남긴다.

### 12-9. 정상/불량 비교 및 종료 (Q01~Q03, L01~L05)

1. 시험 전에 정상·불량 상태를 별도 확인한 시험품과 반복 횟수를 정한다. 같은 레시피·설정으로 정상군과 불량군을 실행하고 매회 run_id/point_id를 기록한다.
2. 매회 원래 체결 상태와 시험 후 손상·미끄러짐을 확인한다. 재사용 시험품의 상태가 바뀌었으면 별도 표본으로 기록하거나 원상 복구 후 시험한다.
3. 8장 표에 종료 사유·최대 힘·변위·최소 폭·판정 사유를 원본 파일에서 옮긴다. 정상인데 FAIL은 오검출, 불량인데 PASS는 미검출, SYSTEM_ERROR는 별도 건수로 집계한다.
4. 화면과 `inputs.json`, `samples.jsonl`, `inspection_results.json`, `judgment_results.json`, `job_summary.json`, `status.json`을 실행 식별자별로 대조한다. STOP/오류 실행과 정상 완료를 구분한다.
5. 원장에 통과·실패·미실행·해당 없음 및 증거 경로를 기록한다. 1차 수정 사항은 변경 버전과 영향 항목을 남기고 2차에서 다시 확인한다.
6. 최종 자세·Job 종료·정지 상태를 확인한 뒤 HMI와 검사 프로그램을 정상 종료한다. 현장 장비 종료 절차에 따라 마무리하고 두 회차 자료를 보관한다.
