# 구현 상태와 남은 확인 재점검

> 아래 본문은 수정 전 재점검 이력이다. 이후 사용자 승인으로 U01/U02를 수정했다. 접근 미도달은 후속 파지를 막고, 현재 Access의 수동 HOME은 직접 Home으로 간다. [수정 후 검증](04_운영코드_반영_검증요약_v4.md)에서 자동시험 257건·정량 비교 72건 통과를 확인한다.

기준일: 2026-09-25 · 대상: 최종결론 18번의 구현 상태·U01/U02/U03·R01~R05

이번 점검은 코드 열람, 기존 오프라인 시험, 장비 API만 대체한 추가 재현이다. 운영 코드와 HMI 코드는 변경하지 않았다. 가상 드라이버나 실물 로봇도 기동하지 않았다.

## 1. 우선 결론

| 항목 | 재점검 결과 | 다음 처리 제안 |
|---|---|---|
| U02 접근 미도달 | Entry pose를 100 mm 못 가도 후속 파지·Pull 실행을 재현 | 접근의 미도달 허용을 제거하고 실제 도달 후에만 #04 시작. 접촉 Entry/Pull 정책은 유지 |
| U01 Access에서 수동 HOME | 일반 호출은 Open→Escape→Access→Home, verified 호출은 Home만 실행 | 현재 Access 여부를 자세로 재확인해 직접 Home 경로를 선택하도록 일관화 권고 |
| U03 초기 범위 | 합의 완료 사항, 확장 구상, HMI 책임, 물리 검증이 혼재 | 아래 분류로 나누며 전부 필수 미구현 작업으로 취급하지 않음 |
| R01~R05 | 물리 검증 항목으로 유지 | 실제 Tool 방향·간섭·파지·판정 조건을 기록과 함께 확인 |

U02는 단순히 코드가 의심되는 단계에서 실제 재현된 불일치로 상태를 갱신한다. 사용자가 미도달 허용을 설명한 대상은 Entry pose 이후 접촉 진입과 Pull이다. 접근 실패를 정상 도달 체크포인트로 기록하는 것은 이 설명과 맞지 않는다.

U01의 과거 직접 Home 합의는 Work Finish 이후 Access 상황을 대상으로 했다. 이후 자동 Home을 없앤 현재 수동 명령까지 이미 적용되었다고 단정하지 않는다. 다만 같은 Access 위치에서 START는 후퇴를 생략하고 HOME은 후퇴하는 현재 차이는 불필요하며, 위치 확인을 기준으로 통일하는 것이 타당하다.

## 2. 재현 내용과 기존 시험의 한계

### U01 — Access에 있는데도 일반 수동 HOME은 탈출 반복

현재 시스템 레시피의 실제 Access 좌표로 HomeReturnSequence를 시작했다. 로봇 위치/명령 API는 메모리 대역이며 경로 선택은 운영 코드다.

| 입력 | 실제 선택 경로 | 명령 순서 |
|---|---|---|
| run(at_verified_access=False) | WORK_AREA_ESCAPE | OPEN, ESCAPE, ACCESS, HOME |
| run(at_verified_access=True) | VERIFIED_ACCESS_HOME | HOME |

MainSequence.request_home_return()은 home_return()을 기본값으로 호출한다. 직접 Home 분기 자체는 있지만 일반 수동 명령에서 자동으로 선택되지 않는다. 기존 verified Access 시험은 플래그를 직접 True로 넣으므로 사용자 HOME 명령이 해당 분기를 이용하는지까지 보장하지 않는다.

### U02 — 실제 공통 모션에서도 접근 미도달 후 검사 진행

SequenceMotion과 InspectionSequence를 그대로 사용하고 raw Robot/Gripper API만 합성 입력으로 대체했다. 시간도 가상 시계로 진행했으며 실시간 60초나 로봇 이동은 발생하지 않았다.

| 관측 | 결과 |
|---|---|
| Entry 목표 | Z=0 mm |
| 접근 후 실제 TCP | Z=100 mm 유지 |
| 공통 목표 확인 제한 | 가상 시간 60초 |
| 반환 stop_reason | TARGET_NOT_REACHED |
| 위치 오차 | 100 mm |
| 기록 체크포인트 | ENTRY_REACHED 포함 |
| 후속 동작 | Soft Grip 실행, Pull 판정 요청 1건 |

point_transition()의 allow_incomplete=True로 공통 모션이 예외 대신 미도달 결과를 반환한다. 호출부가 그 결과를 확인하지 않고 ENTRY_REACHED를 기록해 #04로 넘어간다. 이후 접촉 진입은 잘못된 현재 위치에서 시작할 수 있다.

기존 test_recipe_iterates_point_transition_adaptive_pull_and_return은 Entry 접근의 True 인자를 기대한다. 따라서 기존 시험이 통과하더라도 사용자 의도와의 불일치를 잡지 못한다. 수정 시에는 단순 기대 인자 교체뿐 아니라 접근 미도달에서 Soft Grip·접촉 이동이 실행되지 않는지를 검증해야 한다. 접촉 Entry/Pull의 미도달 기록·계속 진행 시험은 그대로 유지한다.

## 3. 다시 확인한 구현

| 구현 | 확인 범위 |
|---|---|
| START 위치별 Access 준비 | Home/Access/작업영역 분기, 준비 실패 시 검사 미실행 시험 |
| 완료 후 Access 대기 | 자동 Home 없음, 최종 Access 실패 시 완료 불가 시험 |
| busy 제어 제외 | 운영 소스에서 RG2 입력 보관과 샘플 기록만 사용; busy 유지 입력 파지 시험 |
| Hard 완료 timeout 복구 | Pull 생략, 포인트 SYSTEM_ERROR, Open/복귀 성공 후 다음 포인트; 복구 실패 중단 시험 |
| 접촉 Entry/Pull 미도달 | 실제 변위·종료 사유 기록, 일반 이동 예외와 구분하는 시험 |
| 판정 | 힘·거리·폭 경계와 오류 분기 시험. 물리 임계값 적합성은 별도 |

모든 그리퍼 문제가 Job 중단 없이 처리된다는 뜻은 아니다. Open 실패, 피드백 통신 실패, 복귀 실패와 STOP은 계속 진행 대상으로 보지 않는다.

## 4. U03 재분류

| 주제 | 올바른 분류 | 근거·처리 |
|---|---|---|
| 독립 entry_direction/connector axis 입력 | 방향 기준 합의 완료 | Entry ZYZ에서 Tool +Z 계산. 별도 방향 필드를 추가하는 것이 남은 필수 작업은 아님 |
| contact_area·영역 밖까지 반복 Escape | 현행 정책 정리 완료 / R03 실물 검증 | 지정 거리 30 mm 후퇴 후 Access. 30 mm의 물리 적합성은 확인 필요 |
| Micro-Wiggle/Fine Alignment | 초기 확장 요구, 현 상세 시퀀스에 없음 | 초기 BRD FR-06에 있으나 v3 #04는 Soft→Entry→Hard. 추가해야 할지 범위 판단 대상 |
| 별도 힘 유지시간 시험 | 초기 컨셉과 이후 상세 설계의 차이 | 초기 결과 컨셉에 유지시간 언급, 현 #05에는 별도 hold 단계 없음. 누락 구현으로 바로 확정하지 않음 |
| MISSING/slip·DETACHED 분류 | 결과 계약·판정 기준 차이 | v3의 MISSING과 현 PASS/FAIL/SYSTEM_ERROR가 다름. 실물 분류 기준과 HMI 결과 계약을 함께 검토 |
| HMI DB 저장 완료 ACK | HMI와 공동 계약 영역 | 로컬 JSON 저장과 다름. 현재 db_saved=false이며 검사측 단독 확정 불가 |
| CSV 출력 | 출력 형식 확장 | 현재 JSON/JSONL 증거가 있음. CSV 부재만으로 검사 시퀀스 미완성이라고 하지 않음 |
| 자동 충돌 경로 생성 | 현행 제공 기능 아님 | 교시·설정 경로 사용. 이 문서가 새 필수 경로 계획 요구를 추가하지 않음 |

이 분류는 초기 요구를 삭제 승인했다는 뜻이 아니다. 이미 합의한 정책을 재질문할 사항과 구분하고, 실제 추가 범위를 별도로 판단하기 위한 정리다.

## 5. 실물 검증은 무엇이 남았는가

| 항목 | 남은 확인 |
|---|---|
| R01 방향 | 각 Entry의 Tool +Z가 실제 케이블 진입 방향과 맞는지 |
| R02 해제 | Home Escape의 25 mm Open이 실제 파지를 풀고 인접 배선과 간섭하지 않는지 |
| R03 경로 | 현재 Tool 반대 30 mm 후퇴와 Access MoveJ가 실물에서 충분하고 무간섭인지 |
| R04 파지 | 목표폭 또는 1.5초/0.2 mm 폭 안정화가 실제 정상 파지와 맞는지; 실제 힘 도달 확인과는 다름 |
| R05 판정 | LAN 15 N/5 mm, 고정 폭 16 mm 등 기준의 정상·불량 분포 적합성 |

보존된 실물 기록은 정상 두 포인트(LAN_L2/LAN_L5)와 half-coupled 한 포인트(LAN_L5)다. LAN_L5는 정상 18.716 N/3.049 mm, 불량 10.017 N/25.037 mm로 구분된다. 그러나 각 조건의 반복 분포나 BMW를 포함한 전체 케이블 적합성까지 확정할 표본은 아니다. 반체결의 원본 결과는 PENDING/result=null이며 당시 결과 저장 완료 증거가 아니다.

추가 계측 주의점: 공통 sample()은 폭→TCP→힘을 순차 조회한다. 폭·TCP 읽기 시각과 힘 기준 시각을 남기지만 하드웨어 동시 샘플링은 아니다. 초기 BRD FR-10의 동기화가 요구하는 정밀도는 아직 정량 수용 기준이 없다. R05 실물 검증에서 시간차가 힘·변위 판정에 미치는 영향을 함께 확인해야 한다.

## 6. 이번 시험과 재현 자료

기존 관련 오프라인 시험 165건과 추가 관찰 재현 3건, 합계 **168 passed**. pytest 캐시 생성 권한 경고 2건은 있었고 시험 실패는 없다. 추가 3건의 PASS는 현재 현상을 재현했다는 의미이며 U01/U02가 설계상 옳다는 뜻이 아니다. 기존 전체 자동검증 236건을 새로 모두 수행했다고 보고하지 않는다.

- 관찰 결과 JSON — 로컬 자료: `results/implementation_review/20260925_U01_U02/observed.json`
- 시험별 JUnit 결과 — 로컬 자료: `results/implementation_review/20260925_U01_U02/pytest.xml`
- 추가 재현 코드 — 로컬 자료: `results/implementation_review/20260925_U01_U02/test_remaining_review.py`

**아래 명령은 수정 전 코드의 문제 재현용이다. 현행 코드에서는 옛 API/기대 동작이 바뀌어 통과하지 않으므로 현행 검증에는 사용하지 않는다. 현행 검증은 diagnostics/check_inspection.py --with-ros를 사용한다.** 수정 전 추가 재현 3건의 실행 명령을 이력으로 남긴다. 원본 재현 코드는 관찰 JSON을 /tmp/cccis_remaining_review_evidence.json에 기록한다. 위 observed.json은 이번 실행의 보존본이다.

```bash
source /opt/ros/jazzy/setup.bash
source ros_ws/install/setup.bash
PYTHONPATH="$PWD/ros_ws/src/cable_inspection:$PWD/ros_ws/src/cable_inspection/test:${PYTHONPATH:-}" python3 -m pytest -q -p no:cacheprovider ros_ws/results/implementation_review/20260925_U01_U02/test_remaining_review.py
```

기존 시험 범위: test_start_work_access.py, test_design_alignment.py, test_sequence_offline.py, test_inspection_sequence.py, test_motion_feedback.py, test_inspection_judgment.py.
