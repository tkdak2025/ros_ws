# 실행과 정량검증 가이드

버전: v4 · 기준일: 2026-09-25 · 범위: 검사파트와 HMI 통신 계약

[v4 문서 안내](../../00_문서안내_v4.md) · [변경 근거·확인 항목](../../01_commons/02_변경추적_및_확인항목_v4.md)

## 1. 어떤 시험인지

| 방식 | 확인 범위 | 확인하지 못하는 것 |
|---|---|---|
| diagnostics 자동검증 | 실제 시퀀스/판정 코드에 합성 힘·폭·위치·시간 입력, 모의 ROS 통신 | 실제 케이블 접촉·간섭·센서 정확도 |
| virtual 전체 운전 | 가상 드라이버의 모션 서비스·순서·자세·상태 전이 | 실물 저항·그립력·실제 체결 적합성 |
| real 현장 시험 | 실제 방향·해제·접촉·판정 분포 | 별도 증거 없이 다른 제품 전체로 일반화 |

## 2. 자동 재현·정량검증

`ros_ws`에서 실행한다. 설치된 ROS와 빌드된 검사 인터페이스, pytest가 필요하다.

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 src/cable_inspection/cable_inspection/diagnostics/check_inspection.py --with-ros
```

`--with-ros`를 빼면 기본 오프라인 시험·정량 비교를 실행한다. ROS 시험은 격리된 domain 232/LOCALHOST의 모의 통신이며 로컬 드라이버 패키지 환경을 필요로 한다. 실물 구동 명령을 보내는 프로그램이 아니다.

`--output /tmp/inspection-check-v4-001`로 새 출력 폴더를 지정할 수 있다. 기존 폴더는 덮지 않는다. 기본 출력은 `ros_ws/results/checklist/<실행시각>/`다. 실행기는 패키지의 test 코드·입력 대역을 함께 사용하며 단독 파일 복사만으로 동작하지 않는다.

실행 기준은 코드 안 CHECKLIST 55개 항목이다. MD 파일을 파싱하지 않으므로 이번 문서 이동은 검증 실행기에 영향을 주지 않는다. 하나의 시험으로 A01/A02처럼 여러 체크 항목을 확인할 수 있으며 같은 시험을 반복 실행할 필요가 없다.

| 산출물 | 내용 |
|---|---|
| report.md | 기대/관측/단위/오차, 항목별 자동검증 범위, 개별 결과 |
| offline.log/xml | 오프라인 pytest 로그·JUnit |
| ros.log/xml | 선택한 모의 ROS 통합시험 |
| evidence/*.json | 고정 입력과 계측·명령 증거 |

종료 코드 0은 수행한 자동검증 통과다. 시험 실패·건너뜀·실행 오류는 비정상 결과이며 report와 로그를 확인한다. 제품 결과 FAIL을 기대한 시험도 기대대로 나오면 검증 PASS다. 수치 비교 1e-6 같은 허용값은 계산 비교 정밀도이며 실물 센서 정밀도가 아니다.

## 3. virtual 전체 시퀀스

각 터미널을 `ros_ws`에 두고 같은 DDS 도메인을 사용한다. 아래는 기존 확인 환경의 명령이다. 로컬에 m0609_rg2_bringup과 DRCF 가상 컨트롤러가 준비되어 있어야 한다.

```bash
source /opt/ros/jazzy/setup.bash
source /home/rokey/ws_cobot_pjt/ws_dsr/install/local_setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=151 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

터미널 1 — 장비 가상 드라이버:

```bash
ros2 launch m0609_rg2_bringup bringup.launch.py mode:=virtual host:=127.0.0.1
```

터미널 2 — 검사 실행:

```bash
ros2 launch cable_inspection inspection.launch.py robot_mode:=virtual control_mode:=terminal results_dir:=/tmp/cccis_virtual_v4
```

터미널 3 — 제어:

```bash
ros2 run cable_inspection sequence_console
```

1 START / 2 PAUSE / 3 RESUME / 4 STOP / 5 HOME / 6 레시피 선택 / 7 상태 조회. START와 HOME은 실제로 모션을 일으키는 입력이다. launch의 robot_mode 기본값은 real이므로 가상 시험에서 virtual을 명시한다. 검사 launch가 장비 가상 드라이버까지 자동으로 띄우지는 않는다.

HMI 입력 시험도 가능하다. 검사 실행에 `control_mode:=hmi robot_mode:=virtual`을 사용하고 전체 Recipe 서비스와 hmi_heartbeat로 제어한다. robot_mode와 control_mode는 별개다.

## 4. real과 virtual의 차이

상위 검사 순서는 동일하다. 다만 가상 TCP/Tool 등록 절차, 그리퍼 명령 단위 변환, MoveJ 도달 확인은 장비 모드에 맞춰 다르다. virtual은 교시 TASK와 가상 FK 차이 때문에 관절 0.1° 기준으로 MoveJ를 확인한다. real의 TCP 위치 0.5 mm/자세 1° 기준을 완화한 것이 아니다.

실물 HMI 운전은 `control_mode:=hmi robot_mode:=real`이다. real 장비 연결은 별도 robot_bringup 설정을 사용한다. virtual의 힘이 낮아 MAX_DISTANCE/FAIL이 나와도 소프트웨어 순서 실패라고 단정하지 않는다.
