# 05. 시퀀스 보류항목 반영 결과

작성: 2026-09-23. 이전 [04 대조 문서](04_시퀀스_설계구현_대조_및_보류체크_2026-09-23.md)의 보류 항목을 재개한 결과다. 코드 반영과 실물 검증은 구분한다.

## 확정된 사용자 조건

- 모든 보류 항목 진행.
- 현재 Tool 자세의 역방향으로 탈출. 기존 Entry 접근축 Tool +Z에 대응하여 Tool −Z 적용.
- 그리퍼는 약 25 mm Open 후 탈출.
- LAN 기준 힘은 기존 15 N 유지.
- Home은 기존 전체 관절 0도로 직접 MoveJ 유지.

## 반영 현황

| 항목 | 반영 내용 |
|---|---|
| H01 시작/노드 분리 | StartInspection 전체 레시피 서비스, request_id, snapshot, 상태 분리 유지. 활성 설계 문서에 반영 |
| H02 Home | 작업영역 내부에서 25 mm Open 및 idle/실측 폭 확인 → Tool −Z Safe Escape → Work Access → Home. 외부에서는 직접 Home. route=[home_pose], 관절 허용오차 0.1도 설정화 |
| H03 Entry | Ready MoveJ → Entry MoveL, TARGET_REACHED 필수. 미도달·timeout에서 Grip/Pull 진행 차단 |
| H04 방향/폭/판정 | Entry ABC 기반 방향, Soft 기준 폭, Pull 최소 폭 16 mm 미만 FAIL_GRIP_WIDTH, PASS/FAIL/SYSTEM_ERROR 유지. 이전 MISSING/Hard 기준 폭 설계 갱신 |
| H05 수치 | LAN 15 N 유지. HMI snapshot의 양수 조건 사용. Entry/Pull 최대거리 25 mm, timeout 10 s 상한 검증. 속도는 레시피 값 사용 |
| H06 완료 게이트 | 모든 모션/Grip/Pull SUCCESS, 판정 COMPLETED, PASS/FAIL, 로그 저장 완료 필요. ERROR/INCOMPLETE/PENDING/SYSTEM_ERROR는 자동 최종 Home 및 정상 완료 차단 |
| 기록 보완 | 최종 status 갱신 시 STOP 당시 context 보존, 기록 정리 후 최종 완료 기록. 이전 구현의 덮어쓰기 문제 수정 |

Open 확인은 기존 그리퍼 폭 허용오차 2.5 mm를 적용하며, 마지막 확인에서 busy=false와 유한한 실측 폭을 요구한다. 실제로 케이블에서 해제되었는지 센서로 판정하는 기능은 아니다.

SYSTEM_ERROR에서는 기존 Work Finish 정책처럼 Access에서 보류/PAUSE한다. 자동 재검사나 자동 Home을 시작하지 않는다. STOP으로 Job을 종료하고 원인 해소 후 수동 HOME/새 START를 진행한다.

## Safe Escape 해석 정리 — 해결

영역 경계까지 완전히 탈출해야 한다는 해석을 철회했다. 사용자는 기존 Safe Escape를 현재 Tool 자세 반대로 30 mm 후퇴하는 것으로 구체화했다. 별도 contact_area는 만들지 않는다. 작업영역 내부에서는 25 mm Open 확인 → Tool −Z로 30 mm 후퇴·도달 확인 → Work Access → 0도 Home을 적용한다. 외부 분기는 기존 직접 Home이다.

후퇴 뒤 영역 내부라는 이유로 실패시키지 않는다. 목표 미도달·모션 오류는 후속 이동을 차단한다. 최신 재대조/검증은 [06 문서](06_시퀀스_전체_재대조_결과_2026-09-23.md)를 따른다.

## 검증

- 당시 오프라인 테스트 **148 passed**. 후속 수정 결과는 06 문서 참조.
- Open 실패/폭 미도달/busy 지속, 당시 경계 기반 탈출(후속 고정 후퇴 검증으로 대체), Home 단계 실패 시 후속 이동 차단 검증.
- Entry 목표 미도달 시 파지/Pull 미실행 검증.
- SYSTEM_ERROR 발생 Job은 Access에서 PAUSE하고 자동 최종 Home을 수행하지 않는 전체 흐름 검증.
- 정상/실패 최종 기록 및 STOP Context 보존 검증.
- `git diff --check` 통과.
- ROS 노드 실행·실물 명령·이동 시험 없음. 소스 코드로 테스트했으며 이번 변경 후 colcon 재빌드는 수행하지 않음.
