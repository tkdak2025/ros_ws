# CCCIS 검사파트 구현 및 개선사항

| 영역 | 항목 | 구분 | 시도·구현 내용 | 문제·제약 및 이유 | 변경 내용·현재 결론 |
| ---------- | -------------------- | -------- | ------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **HMI** | 실시간 검사 모니터링 | 구현 | 작업 상태, 로봇 상태, 측정값, 포인트별 판정과 사유 표시 | 화면 상태만으로 실제 로봇의 운전 가능 여부를 판단할 수 없음 | 로봇 실측 상태와 검사 작업 상태를 구분해 표시. **실물 검사 결과 표시 확인** |
| **HMI** | 검사 이력·Excel 저장 | 구현·변경 | 검사 결과를 조회하고 외부 파일로 저장 | 기존 CSV는 요구한 Excel 파일 형식과 달랐음 | `openpyxl` 기반 **`.xlsx` 출력으로 변경**. 검사 결과·요약·원본 시트 구성, CSV 대체 저장 제거 |
| **HMI·검사** | ROS 2 기반 모듈 분리 | 구현 | HMI 통신, 시퀀스, 로봇, 그리퍼, 레시피, 판정을 분리 | 통신·장비 제어·판정이 섞이면 오류 위치와 변경 영향을 추적하기 어려움 | 역할별 모듈과 단일 모션 Worker 구성. **START와 HOME의 동시 실행 방지** |
| **HMI·검사** | 레시피 기반 검사 | 구현·변경 | 레시피로 좌표·순서·파지 폭·힘·판정 조건 설정 | 파일 변경이 HMI 보관값이나 이미 시작한 검사에 즉시 반영되는 것은 아님 | HMI가 START 시 전체 레시피를 전달하고, 검사 측은 **실행 복사본을 고정**하여 사용 |
| **HMI·검사** | 레시피 미반영 의심 | 문제 분석·개선 | 선택 레시피와 실제 이동 위치 비교 | 소스·설치본·HMI 보관값을 혼동할 수 있었고, 검사 전 공통 이동을 다른 포인트 이동으로 오인할 여지도 있었음 | 수신 레시피 ID, 실행 포인트, Ready·Entry의 joint/task를 로그로 출력. **레시피 전달 문제와 이동 경로 문제를 분리해 추적** |
| **HMI·검사** | 레시피 선택 책임 | 설계·후속 과제 | 로컬·HMI 레시피 설정을 `ccc_hmi_node`에서 담당하도록 방향 설정 | 현재 Main·Recipe에도 선택·보관 처리가 남아 있음 | 전체 레시피 전달 경로는 구현. **선택 책임을 HMI 노드로 완전히 일원화하는 리팩터링은 미완료** |
| **HMI·검사** | PAUSE·RESUME·STOP | 구현·실물 검증 | 일시정지, 재개, 정지 요청 처리 | PAUSE와 STOP의 의미가 다르며, 이동 중 STOP도 처리해야 함 | 원자 동작 완료점에서 PAUSE, 문맥을 유지해 RESUME, STOP 시 작업 종료. **일시정지 중·이동 중 STOP을 사용자 실물 확인** |
| **HMI·검사** | 재시작·통신 상태 복구 | 구현·검증 | HMI와 검사 프로그램 재시작 후 상태·이력 확인 | 프로그램 재시작으로 통신과 실행 상태가 달라짐 | **통신끊김 → 대기 전환과 과거 결과 조회 확인**. 작업 중 통신 유실의 모든 복구 시나리오는 별도 검증 필요 |
| **검사** | 실물 하네스·LAN 검사 | 구현·확장 | 단일 포인트 접근·파지·Pull·복귀·판정 수행 | 단일 포인트 성공만으로 다중 포인트 이동 경로까지 검증되지는 않음 | 단일 포인트에서 다중 포인트로 확장. 기존 레시피를 유지하며 **03은 2포인트, 04는 4포인트로 재구성** |
| **검사** | Ready 도달 타임아웃 | 실패·원인 해결 | 관절좌표로 MoveJ 후 저장 task와 실측 TCP 비교 | 관절은 도달했지만 TCP가 약 **11.5 mm** 달라 다음 단계로 진행하지 못함 | 직접 교시와 FK 대조로 **J5 `-111.56°` → `-113.56°` 오기 확인**. 관련 레시피·상부 복귀점을 수정했고, 정정 task와 FK 오차는 약 **0.006 mm** |
| **검사** | MoveJ 완료 판정 | 변경·범위 조정 | 이동 완료를 실측 피드백으로 확인 | HOME에서 잘못 짝지어진 task 때문에 관절 도달 후에도 대기 발생 | **HOME MoveJ는 정지＋절대 관절각 기준**으로 변경. 일반 검사 MoveJ의 전역 변경은 적용하지 않고 좌표 오기를 수정 |
| **검사** | 고정 30 mm Safe Escape | 실패·방식 변경 | 툴 자세를 유지하며 Tool 접근축 반대로 30 mm MoveL | 현재 관절 자세에 따라 `NOT REACHABLE` 발생. 작업영역 안이라는 사실만으로 직선 이동 가능성을 보장할 수 없음 | **HOME에서 고정 직선 이탈을 제거**, 영역별 교시 경유점으로 MoveJ 후 Home 복귀. **START의 기존 30 mm 이탈은 유지되어 후속 과제** |
| **검사** | 현재 자세 기반 HOME 복귀 | 설계·구현·제약 | 마지막 작업 기록에 의존하지 않는 복귀 방식 검토 | 재시작·수동 조작·중간 STOP으로 마지막 작업 상태를 신뢰하기 어려움 | **실측 BASE TCP의 XYZ로 상부·하부/측면 분류**. 해당 경유점 → Home으로 이동, 영역 밖은 자동 복귀 차단. 임의 자세의 충돌 없는 경로 자동 생성은 미구현 |
| **검사** | 작업영역 설정 | 변경 | 신규 교시 위치를 작업영역에 포함 | 기존 경계 밖에 새 모니터암 위치가 존재 | 전체·상부 X 하한을 **-330 mm**, Z 상한을 **800 mm**로 조정. 영역 경계와 탈출 목표 자세를 별도 설정. **영역 포함과 실제 도달 가능성은 별개** |
| **검사** | 그리퍼 초기 닫힘 | 문제 분석·변경 | 초기 힘을 40 N으로 맞춘 후 작업 시작 | 힘 증감 명령이 드라이버에 저장된 이전 파지 폭까지 재전송해 닫힐 수 있음 | **30 mm 폭을 먼저 지정 → 힘을 0 N 기준으로 낮춤 → 10 N 동기화**로 변경. 40 N 상승 초기화 제거. 실물 증상 해소는 추가 확인 필요 |
| **검사** | 그리퍼 Open 폭 | 변경 | 검사 및 START/HOME에서 개방 명령 수행 | Open 명령도 절대 폭 이동이므로 현재 폭보다 작은 목표면 닫힘 발생 가능 | 포인트별 **Soft Open＝Soft Close＋5 mm**, START/HOME 공통 개방 **25 → 30 mm**. 현재보다 항상 더 여는 정책은 미구현 |
| **검사** | 그리퍼 폭 도달 타임아웃 | 실패·완화 | 목표 폭과 실측 폭을 비교해 완료 판정 | 목표 29 mm에 실측 32.5 mm로 약 3.5 mm 차이가 나 기존 허용오차 초과 | 허용오차 **2.5 → 5 mm**로 확대. **타임아웃 완화 조치이며, 폭 오차·기구 문제의 근본 해결은 아님** |
| **검사** | 단계별 파지·미끄러짐 | 구현·튜닝 과제 | Soft Grip 후 Hard Grip으로 검사 파지 수행 | 불안정한 파지 위치에서 미끄러짐이 의심됨. 원인 확정은 못 함 | 파지 폭·개방 폭·교시 위치를 조정. **파지 안정성 튜닝은 진행 과제**, 해당 FAIL을 체결 불량만으로 단정하지 않음 |
| **검사** | 힘·변위 기반 판정 | 구현·실물 검증 | Pull 중 힘과 변위를 측정해 PASS/FAIL 판정 | 감속 정지 중 실측 힘이 정지 기준을 초과할 수 있음 | 힘 기준과 변위 합격 기준을 분리. **허용 변위 초과 FAIL 및 최대 힘 16.41 N 표시·기록 확인** |
| **검사** | 힘제어·순응제어 | 구상·미구현 | 접촉·인장 검사에 힘을 활용하는 제어 검토 | 현재 코드는 목표 힘을 유지하거나 순응 강성을 제어하지 않음 | 현 구현은 **MoveL＋힘 감시＋임계값 정지**. Pull 15 N은 유지 목표가 아닌 정지 기준. **순응제어는 Drop 확정이 아니라 후속 구현 과제** |
| **검사** | 서비스 응답 타임아웃 | 문제 대응·변경 | 로봇 서비스 응답을 제한시간 동안 대기 | 힘·시스템 조회에서 5초 응답 제한 초과 발생 | 로봇 서비스 제한을 **5 → 30초**로 확대. 이동 완료 60초·그리퍼 완료 20초와 구분. **응답 지연 원인을 해결한 조치는 아님** |
| **HMI·검사** | 자동시험과 실물 검증 병행 | 구현·검증 전략 | 모의 피드백 회귀시험과 실제 로봇 시연 병행 | 자동시험은 충돌·미끄러짐·실제 케이블 해제를 보장하지 못함 | 최신 관련 회귀시험 **57개 통과**. 실물 확인 항목과 미검증 항목을 분리하고, 변경된 경로는 과거 검증 결과를 그대로 승계하지 않도록 문서화 |
